## 0. 开篇：需求真伪辨析（本规划的立论基础）

这一节决定了后面所有优先级的排法，先说清楚。

**用户嘴上说的**：做一个五子棋出海独立站。
**真正要解决的问题**：中国棋类品牌在海外没有一个「低门槛入口 + 多品类承接 + 文化叙事」的聚合阵地——竞品要么单品类工具化（Gomoku.com），要么单品类但重运营（Xiangqi.com）。

**推论（关键）**：MVP 的成败判据 **不是「五子棋做得好不好玩」**，而是两条：

1. **自然流量能否起量**——五子棋是钩子，钩子的价值在于被搜索到、被分享出去，不在于 AI 棋力多强。
2. **新用户能否产生第二次行为**——第二次访问，或点开第二个棋种。这才验证「聚合平台」假设成立。

**这条推论直接改变工期分配**：MVP 里 SEO/SSR、多语言、埋点基座、对局分享卡这四项「非游戏能力」必须与棋盘同等优先级，**不能**把 0–1 月的工期全砸在 minimax 调参上。竞品 Gomoku.com 已经证明「AI 够用即可」——它上线首年 402 万盘对局靠的是 15 种语言和 PWA，不是引擎强度。

> 需要向主理人确认的一点：如果用户的真实诉求其实是「卖棋具（DTC）」，那本规划的整体排序需要推翻重来。目前按「数字平台起盘」假设推进，见待决策 D2。

## 1. 产品定位与核心价值主张

### 1.1 定位（一句话重申）

**弈界 YiBoard —— A global home for Chinese strategy board games：从五分钟学会的五子棋开始，走进中国棋艺的完整世界。**

对外传播口径（英文主口径，非中文用户是主要受众）：
> Start with Gomoku in five minutes. Stay for a thousand years of Chinese strategy.

### 1.2 核心价值主张（3 条，均为可对抗竞品的差异化，不是通用卖点）

| # | 价值主张 | 差异化对手 | 为什么竞品做不到 / 没做 |
|---|---|---|---|
| **VP1** | **一个账号玩遍中国棋**：五子棋 → 象棋 → 黑白棋 → 围棋，统一段位、统一好友、统一复盘 | Gomoku.com（只有五子棋）、Xiangqi.com（只有象棋）、OGS（只有围棋） | 三家均为单品类深耕型产品，横向扩品类会稀释其既有定位与技术栈；对我们是增量，对它们是自我否定 |
| **VP2** | **零门槛跨文化入口**：图形化棋子 + 60 秒图解规则 + 免注册好友房，非华人不需要任何中国文化前置知识就能开局 | Xiangqi.com 已做图形化棋子，但入口是象棋（规则复杂度中等）；我们的入口是五子棋（规则复杂度极低） | 入口品类的选择是结构性差异，不是功能差异，无法被短期抄袭 |
| **VP3** | **文化叙事而非工具**：每个棋种带「它从哪来、为什么这样下」的本地化内容，把对弈变成文化接触点 | Gomoku.com 文化叙事为零；雀魂用二次元皮而非文化本体 | 内容生产依赖中文母语团队对棋史的理解 + 高质量本地化，这恰是中国团队的天然优势，也是海外团队的成本洼地 |

**主动放弃的卖点**（避免摊薄）：不做「最强 AI」、不做「最全变体规则」、不做「最快匹配」。这三条是工具型竞争维度，赢了也建不起护城河。

## 2. 目标用户分层与优先级

PRD §11 列了 5 类画像。规划层要回答的是：**先打谁、后打谁、谁根本不打。**

### 2.1 分层与打法顺序

| 优先级 | 用户层 | 在漏斗中的角色 | 何时主攻 | 触达手段 | 成功信号 |
|---|---|---|---|---|---|
| **T0（首批主攻）** | **休闲尝鲜者**（海外普通网民，被「5 分钟上手」吸引） | 流量池 + 裂变源 | 0–1 月 | SEO 长尾词（`play gomoku online` / `gomoku with friends`，竞争度 < 0.3）、对局分享卡回流 | 首局完成率、好友房创建率 |
| **T1（首批次攻）** | **策略游戏爱好者**（玩过 Chess / Othello / Catan，想尝鲜） | 留存基本盘 + 口碑放大器 | 0–3 月 | Reddit r/boardgames、r/chess、BoardGameGeek | D7 留存、人均周对局数 |
| **T2（第二阶段）** | **海外华人 / 汉学圈** | 社区种子 + 内容共创 | 1–3 月 | 华人 KOL、海外中文学校、孔子学院圈层 | 象棋对局占比、UGC 提交量 |
| **T3（第二阶段）** | **学习者**（想系统学象棋/围棋） | 高 LTV 变现层 | 3–12 月 | YouTube 教程 SEO（CPM $18.6，反证该受众商业价值高） | 会员渗透率、课程完课率 |
| **T4（后置/可能不打）** | **收藏 / 礼品用户**（买棋具） | 变现溢出 | 12 月后或不做 | DTC 站、TikTok 种草 | AOV、复购率 |

### 2.2 三条分层决策的理由

**为什么 T0 是休闲尝鲜者而不是策略爱好者？**
策略爱好者人数少、要求高、对「又一个五子棋站」天然挑剔，冷启动期打他们会得到大量「不如 Lichess/Chess.com」的负面反馈。休闲尝鲜者对功能完备度容忍度高，且是分享裂变的主要贡献者。**先用休闲层堆量与堆分享，再用产品成熟度接策略层。**

**为什么海外华人不是 T0？**
反直觉但必须说清楚：华人圈易触达、易起量，但会把产品带向「中文优先 + 象棋优先」的路径，与「非中文用户 > 50%」的长期目标背道而驰。**冷启动期最危险的事，是被最容易获得的用户拉偏产品方向。** 华人层放在 T2，等英文主界面与非中文用户占比站稳后再引入，此时他们成为社区种子而非方向绑架者。

**T4 为什么可能不打？**
实体 DTC 需要供应链、CPSC/CE-EN71/FSC 认证、外观专利规避（近 3 年 17 起诉讼）、商标注册。这套投入与数字侧几乎零复用。在自然流量未起量前，DTC 没有任何杠杆——它只是把一个流量生意做成了一个库存生意。详见待决策 D2。

## 3. MVP 范围定义（0–1 月）

**MVP 一句话目标**：用最小成本验证「五子棋钩子能否带来可持续的自然流量，且新用户愿意回来第二次」。

### 3.1 IN SCOPE（做，共 11 项）

| 分类 | 交付项 | 验收要点 |
|---|---|---|
| 对弈核心 | 五子棋人机对弈（3 档难度：入门/标准/挑战） | AI 单步响应 P95 < 500ms；入门档新手胜率 40–60% |
| 对弈核心 | 好友房（生成分享链接，**受邀方免注册可下**） | 从点击链接到落第一子 < 15 秒 |
| 对弈核心 | 全球快速匹配（实时） | 匹配等待 P50 < 20 秒（低在线时降级为「匹配不到即转 AI」） |
| 增长基建 | SEO 落地页 + SSR / 预渲染 | 每个棋种 + 每个语种有独立可索引 URL；Lighthouse SEO ≥ 95 |
| 增长基建 | 多语言 i18n（首批 4 语，语种待定见 D7） | 界面零硬编码文案；语言可通过 URL 路径切换（利于 SEO） |
| 增长基建 | **对局结果分享卡**（OG image + 深链回落） | 分享卡含终局棋形图 + 一键「Play me」深链 |
| 增长基建 | 埋点与分析基座 | 见 §7 事件表；上线即可查漏斗 |
| 留存基础 | 账号体系（邮箱 + Google/Apple OAuth） | 匿名对局记录可在注册后合并 |
| 留存基础 | 基础段位 / ELO + 全球排行榜 | ELO 初始分与 K 值可配置，无需发版调整 |
| 上手引导 | 图形化规则教程（60 秒，无文字也能看懂） | 首次访问用户完成率 ≥ 70% |
| 可达性 | PWA 可安装 + 离线人机对弈 | 断网状态下人机模式可正常开局 |

### 3.2 OUT OF SCOPE —— 「不做」清单与原因

**这一节比 IN SCOPE 更重要。MVP 失败的常见死法不是功能少，是功能多到没有一个做透。**

| 不做的事 | 原因 | 何时重新评估 |
|---|---|---|
| **围棋** | 引擎重（KataGo 需 GPU，算力成本高）；赛道被 OGS/野狐/Tygem 占住；对新用户是劝退项不是吸引项 | Phase 2，且优先考虑接入而非自建 |
| **象棋** | 虽是核心留存品类，但 MVP 阶段上第二个棋种会稀释「验证五子棋钩子」这个唯一命题，导致数据无法归因 | **下阶段（主理人 2026-08-12 拍板延后）**：引擎已定 ElephantEye（LGPL-2.1）→ WASM，排期移入下阶段，见 D9 |
| **原生 App（iOS/Android）** | 商店棋牌类审核有地区限制风险；发版审核拖慢迭代；MVP 阶段所有增长来自 Web SEO 与链接分享，App 无杠杆 | 见待决策 D3，有明确量化触发条件 |
| **社区论坛 / UGC** | 无用户基数时 UGC 是空房子，冷清的社区比没有社区更伤转化；且需要审核人力 | Phase 2，且需 WAU ≥ 3 万才启动 |
| **教学课程体系** | 内容生产是重投入（Xiangqi.com 70+ 课程是多年积累），需先验证留存再投内容 | Phase 2 |
| **实体棋具商城 / DTC** | 供应链 + 三国认证 + 商标 + 外观专利规避，与数字侧零复用；无流量时是纯成本 | 见待决策 D2 |
| **广告变现** | 棋类用户对广告高度反感（Xiangqi.com 把 NO ADS 做成品牌资产）；且 MVP 期 DAU 下广告收入可忽略不计，用口碑换几十美元不划算 | Phase 2 后评估，且仅限「激励视频换皮肤」，绝不换棋力优势 |
| **周赛 / Swiss 赛事** | 赛事需要用户密度，人不够时开赛会因凑不齐人而公开失败 | Phase 1 末尾，需同时在线 ≥ 200 |
| **Renju 禁手模式** | 面向硬核连珠玩家（T1 中的极小子集），对 T0 是认知负担 | Phase 1 |
| **私信 / 好友系统** | 社交功能需要审核与举报机制配套，MVP 期做半套反而引入合规风险 | Phase 1 |
| **自研象棋 / 围棋引擎** | 开源方案（ElephantEye / KataGo）已足够，自研是纯浪费 | 永不 |
| **15 种语言全上** | 先 4 语验证哪些国家真有量，再按数据扩语。盲目铺 15 语 = 15 份翻译成本 + 15 份维护成本换未知回报 | Phase 1 按 GA 国家分布扩至 10 语 |
| **皮肤 / 棋盘主题系统** | 变现优先级低（棋类 IAP 转化远低于麻将类）；但**设计侧必须预留主题 token**，避免后期重构 | Phase 2 |
| **引擎级反作弊** | MVP 期作弊动机低（无排位奖励、无金钱）；基础规则校验（服务端裁决落子合法性）足够 | 排行榜有实质奖励时 |
| **暗色模式** | 非核心；但**设计 token 必须预留**，Phase 1 补齐成本极低，MVP 硬编码颜色则代价高 | Phase 1 |

> **给设计师与架构师的两条硬约束（虽不做，但必须预留）**：
> 1. 颜色/间距/字号全部走 design token，暗色模式与棋盘主题是「预留不实现」，不是「不考虑」。
> 2. 所有 UI 文案走 i18n key，零硬编码；德语/俄语等长词语种需预留 1.6 倍文本膨胀空间，按钮不能定宽。

## 4. 功能优先级矩阵（RICE）

**评分口径**：`Score = (Reach × Impact × Confidence) / Effort`
Reach 1–10（季度受影响用户规模）｜Impact 0.25/0.5/1/2/3｜Confidence 50%/80%/100%｜Effort 人月（1 = 半个月工作量级别的小项，此处按实际人月填）

### 4.1 P0 —— MVP 必做（0–1 月）

| 功能 | R | I | C | E | Score | 为什么是这个优先级 |
|---|---|---|---|---|---|---|
| 埋点与分析基座 | 10 | 1 | 100% | 0.5 | **20.0** | 高分源于极低成本而非最高用户价值。不埋点 = 上线后所有假设都无法证伪，MVP 就白做了。必须第一个落地 |
| 五子棋人机对弈（3 档） | 10 | 3 | 100% | 2 | **15.0** | 唯一的「无网络依赖、无对手依赖」的可玩路径。没有它，任何流量进来都会空转 |
| 好友房 + 免注册可玩 | 8 | 3 | 100% | 2 | **12.0** | 最强裂变机制。免注册是关键——每加一道注册墙，受邀方流失约一半 |
| 对局结果分享卡 | 7 | 2 | 80% | 1 | **11.2** | **规划层新增项**。原 PRD 只在用户流程里提了「分享」，未列为功能项。低成本高杠杆的增长闭环，必须进 MVP |
| SEO 落地页 + SSR | 9 | 3 | 80% | 2 | **10.8** | 自然搜索是零边际成本获客，且长尾词竞争度 < 0.3，是本项目最大的结构性红利。SSR 必须 Day 1 做，后补改造代价极高 |
| 多语言 i18n（4 语） | 9 | 2 | 100% | 2 | **9.0** | 竞品用 15 语吃全球自然量已被验证。i18n 架构必须 Day 1 铺，后补是重构 |
| 账号体系（邮箱 + OAuth） | 6 | 2 | 100% | 1.5 | **8.0** | 留存与归因的前提。但**不能挡在首局之前** |
| 图形化规则教程（60 秒） | 8 | 1 | 80% | 1 | **6.4** | 直接决定首局完成率，是激活漏斗的关键卡点 |
| PWA 可安装 + 离线人机 | 5 | 1 | 80% | 1 | **4.0** | 绕开商店政策风险的核心手段，且安装行为是最强留存信号，需尽早采集该数据 |
| 全球快速匹配（实时） | 7 | 2 | 80% | 3 | **3.7** | 分低是因为 Effort 高（实时基建 + 全球延迟）。但缺它则「在线对弈平台」定位不成立，属**战略必做项，不因 RICE 分低而降级** |
| 基础段位 / ELO + 排行榜 | 6 | 1 | 80% | 1.5 | **3.2** | 竞技成长的最小闭环。可做简版（仅全球榜，不做国家榜） |

> **RICE 的边界说明**：全球快速匹配 RICE 仅 3.7 却必做，说明 RICE 只能排「同类可比项」的序，不能替代战略判断。凡属「定位成立的前提」的功能，一律豁免 RICE 排序。这类项在本表中已标注。

### 4.2 P1 —— 留存与变现验证（1–3 月）

| 功能 | R | I | C | E | Score | 为什么是这个优先级 |
|---|---|---|---|---|---|---|
| 语言扩展至 10 语 | 7 | 1 | 100% | 1 | **7.0** | 边际成本最低的增长杠杆，按 MVP 期 GA 国家分布数据选语种，命中率高 |
| 成就徽章 + 每日任务 | 6 | 1 | 80% | 1 | **4.8** | 提升回访频次的低成本手段，直接服务 D7/D30 目标 |
| AI 复盘（五子棋优先） | 5 | 2 | 80% | 2 | **4.0** | 从「玩」到「学」的转化钩子，也是会员付费点的核心承载 |
| 会员订阅（接 **waffo** 支付/会员层） | 4 | 3 | 80% | 2.5 | **3.8** | Phase 1 的核心命题是「验证有人愿意付费」，而非「赚到钱」。哪怕只有 1% 也是关键信号 |
| Renju 禁手模式 | 3 | 2 | 80% | 1.5 | **3.2** | 承接硬核连珠玩家，是抵御 Gomoku.com（已上 Renju）正面竞争的必要补位 |
| 象棋人机 + 在线 | 5 | 2 | 80% | 3 | **2.7** | **战略权重高于 RICE 分**。这是「多棋种聚合」假设的唯一验证器，且是 Exit Criteria 的判据。~~Phase 1 必上~~ → **主理人 2026-08-12 拍板：排期移入下阶段**（见 D9），验证时点顺延 |
| 好友 / 私信 | 4 | 1 | 80% | 2 | **1.6** | 社交留存，但需配套举报与审核，成本被低估过一次，此处 Effort 已上调 |
| 周赛（Swiss） | 3 | 2 | 50% | 2.5 | **1.2** | Confidence 仅 50%——Xiangqi.com 周赛成功建立在其百万级用户密度上，我们能否复制未知。放 Phase 1 末尾，人不够就延后 |

### 4.3 P2 —— 生态与护城河（3–12 月）

| 功能 | R | I | C | E | Score | 为什么是这个优先级 |
|---|---|---|---|---|---|---|
| **象棋 Xiangqi（下阶段首推）** | 5 | 2 | 80% | 3 | **2.7** | **「多棋种聚合」假设的唯一验证器（主理人 2026-08-12 拍板移入下阶段，见 D9）**。引擎 ElephantEye（LGPL-2.1）→ WASM，许可已核（LIC-2026-001）。下阶段品类顺序中优先于黑白棋 |
| 黑白棋 Othello | 4 | 1 | 80% | 1.5 | **2.1** | **反直觉结论：应先于围棋上线。** 规则简单、引擎轻、海外认知度高（全球经典棋类），是最便宜的品类扩充 |
| 皮肤 / 棋盘主题 IAP | 3 | 1 | 80% | 1.5 | **1.6** | 高毛利但低频。棋类用户的皮肤付费意愿远低于麻将/二次元类，不宜寄予厚望 |

## 5. 分阶段路线图与退出标准

> **Exit Criteria 的用法**：每阶段结束时逐条核对。**任一「熔断条件」触发，立即停止按原计划推进，进入复盘重定向。** 这不是可选流程。

### Phase 0｜0–1 月：验证钩子（Hook Validation）

**唯一命题（v1.1 修订）**：~~五子棋能否带来可持续的自然流量~~ → **产品的转化质量是否达标，且 SEO 引擎是否已正确启动。**

> 修订原因：D6 确认走 SEO 慢热后，「自然流量能否起量」这个问题**在第 30 天根本无法回答**——SEO 的物理规律决定了它要 3–6 个月才给答案。Phase 0 硬要验证它，只会得到一个假的否定结论。
> 因此 Phase 0 的命题下调为两件**当下真的可验证**的事：①进来的人是否玩得下去、愿意回来、愿意分享（转化质量，比率型指标小样本即可判）；②SEO 的技术地基是否铺对（收录/曝光/排名爬升，是流量的先行量）。
> **「流量能否起量」这个命题整体推迟到 Phase 1 出口回答。**

| 里程碑 | 时间 | 关键交付 |
|---|---|---|
| M0.1 技术地基 | Day 1–7 | Next.js SSR 骨架 + i18n 架构 + 埋点基座 + design token 体系 |
| M0.2 单机可玩 | Day 8–16 | 五子棋人机（3 档）+ 图形化教程 + PWA 壳 |
| M0.3 联机可玩 | Day 17–24 | 好友房（免注册）+ 快速匹配 + 服务端落子裁决 |
| M0.4 增长闭环 | Day 25–30 | 账号体系 + 段位/ELO + 排行榜 + 分享卡 + 4 语上线 + SEO 落地页 |

**Exit Criteria（全部达成方可进入 Phase 1）**

> **v1.1 重大校准（因 D6 决策：无 KOL 资源，走 SEO 慢热）**
> 原 v1.0 要求「Day 30 自然搜索周会话 ≥ 3,000」——**该目标在纯 SEO 冷启动下不可能达成，必须废除**。新域名从建立索引到长尾词进入首页通常需 3–6 个月；第 30 天的真实自然流量量级是**每周数十至数百会话**，属统计噪声区间。
> **若沿用流量型阈值，Phase 0 必然「达不到目标」，会触发一次完全错误的熔断，把一个健康产品判死。**
> **因此 Phase 0 的出口判据全部改为「小样本可测的转化质量」+「SEO 技术领先指标」，规模类指标整体右移至 Phase 1/2。**

| 维度 | 指标 | 门槛 | 为什么用这个 |
|---|---|---|---|
| 激活 | 首局完成率（进入棋盘 → 分出胜负/认输） | ≥ 60% | 比率型指标，几百个样本即可置信，不依赖流量规模 |
| 裂变 | 好友房创建数 / 对局发起总数 | ≥ 15% | 同上，且是无 KOL 时唯一的快速增长机制 |
| 裂变 | 分享卡回流率 | ≥ 20% | 验证病毒循环是否闭合 |
| 留存 | D7 留存 | ≥ 12% | 小样本可测；产品是否有回访动机的核心判据 |
| **SEO 领先指标** | 被 Google 收录页面数 | **≥ 200**（各语种落地页 + 棋局页） | 流量的**先行量**。收录不了，后面 6 个月都不会有量 |
| **SEO 领先指标** | Search Console 周曝光量（impressions） | **≥ 2,000** | 曝光先于点击出现，是 SEO 起效的最早信号 |
| **SEO 领先指标** | 目标长尾词进入 Top 50 的数量 | **≥ 10 个** | 排名爬升轨迹比绝对流量更早可判 |
| 规模（参考，不作熔断） | 周新增会话 | ≥ 400 | 仅用于校验样本量是否够算上面的比率 |
| 全球化 | 非中文界面会话占比 | ≥ 60% | — |
| 技术 | AI 单步响应 P95 / 实时对局异常断线率 | < 500ms / < 2% | — |

**熔断条件（触发则停止加功能，回炉重做体验）**
- 首局完成率 < 40% → 上手门槛问题，重做引导与首屏，**不要加棋种**
- D7 留存 < 6% → 产品无回访动机，先解决「为什么要回来」，**不要投流**
- 非中文会话占比 < 30% → 出海假设未成立，需重审 SEO 与语种策略
- **收录页面数 < 50 或周曝光 < 200** → SEO 技术实现有硬伤（SSR/sitemap/hreflang/robots 配置问题），**立即停止功能开发排查技术 SEO**。在无 KOL 的前提下 SEO 是唯一主渠道，这条链路断了整个增长模型就不成立
- **明确不设「流量规模」熔断**：Day 30 的自然流量低是 SEO 的正常物理规律，不是产品失败信号

> **对 PRD §20「会员渗透率 > 3%」的修正建议**
> 行业基准：freemium 自助转化典型区间 **2–5%**，休闲游戏 D30 累计付费转化 **2–4%**，且这是**成熟期**数字。上线首月即达 3% 不现实，会导致团队为凑数把免费体验砍到伤害增长。
> **建议改为分段目标**：Phase 1 出口 1.5%（活跃用户口径）→ 6 个月 2.5% → 12 个月 3.5%。同时**必须锁定口径**：分母用「近 30 日活跃用户」而非「累计注册用户」，两者可差 3–5 倍，不锁口径的 KPI 等于没有 KPI。

- **象棋对局占比 < 3%** → 「多棋种聚合」假设不成立。**立即停止横向扩品类**，转向「五子棋深度 + 竞技生态」单品类路线，Phase 2 全部重排

- ~~MAU 增长连续 3 周环比 < 5%~~ → **v1.1 废除**。SEO 爬坡本身就是非线性的，会出现连续数周平台期后突然跃升（Google 重新评估域名权重），用周环比判死渠道会误杀。**改为：连续 6 周自然搜索曝光量（impressions）无增长 → 判定 SEO 策略失效，启动渠道重估**（曝光比会话更早反映排名变化，且不受点击率波动干扰）

## 6. 北极星指标与 KPI 六维

### 6.1 北极星指标（NSM）

**WQG —— Weekly Quality Games（周高质量对局数）**

**严格定义**（口径不严的 NSM 会被刷）：一局同时满足以下全部条件才计入
1. 双方合计落子 ≥ 8 手
2. 未在开局 30 秒内弃局
3. 终局状态为：五连 / 认输 / 超时 / 和棋（**排除掉线未续**）
4. 非同设备指纹 + 同 IP 的自我对弈
5. 人机对局按 0.5 权重计入（人机有价值但弱于真人对局）

**分解公式（用于定位问题出在哪一环）**
```
WQG = WAU × 人均周对局发起数 × 完局率
```
- WQG 掉了先看是哪一项掉：WAU 掉 → 获客/留存问题；发起数掉 → 内容与动机问题；完局率掉 → 体验/对手匹配质量问题

**为什么不用注册量 / DAU**：注册量可被投流虚增，DAU 无法区分「打开就走」和「认真下了三盘」。WQG 是唯一同时反映规模与质量的单一指标。

| 激活 | `game_started` | 落第一子 | `game_type`, `mode`（ai/friend/match）, `difficulty` |
| 激活 | `game_completed` | 终局 | `game_type`, `mode`, `result`, `moves`, `duration_ms` |
| 激活 | `first_core_action` | 用户首次完成一局 | `game_type`, `time_since_first_visit` |
| 留存 | `session_start` / `session_end` | 会话起止 | `duration_ms`, `games_played` |
| 留存 | `pwa_install_prompt_shown` / `pwa_installed` | PWA 安装漏斗 | `platform` |
| 转化 | `signup_started` / `signup_completed` | 注册漏斗 | `method`（email/google/apple） |
| 转化 | `paywall_viewed` / `upgrade_clicked` / `payment_completed` | 付费漏斗（Phase 1） | `plan`, `price`, `entry_point` |
| 异常 | `error_occurred` | 前端异常 / API 失败 | `type`, `code`, `path` |
| 异常 | `match_timeout` | 匹配超时未成功 | `wait_ms`, `queue_size` |
| 异常 | `disconnect_during_game` | 对局中断线 | `game_type`, `moves_at_disconnect` |

**规范**
- 命名：`{对象}_{动作}`，全小写下划线
- 通用属性：所有事件附带 `user_id`（或匿名 `anon_id`）、`timestamp`、`locale`、`device`、`app_version`
- 隐私：**不上报 IP 原文**（仅存国家码）、**不上报用户输入内容原文**；GDPR/CCPA 下需支持数据导出与删除
- 工具建议：轻量自建 `trackEvent()` 封装 + 可替换后端（Umami / PostHog / Mixpanel 择一），避免与单一 SDK 强耦合

### D3｜先做 App 还是纯 PWA

- **问题**：0–12 月是否投入原生 App？
- **我方倾向**：**纯 PWA 起步，App 由数据触发而非计划触发。**
- **支持理由**：绕开棋牌类商店审核的地区限制风险；无发版审核延迟；与 Web/SEO 共用一套代码与流量；竞品 Gomoku.com 用 PWA 已跑到 400 万盘。
- **反方论点（需正视）**：iOS 上 PWA 的推送能力与桌面留存弱于原生；部分用户存在「必须下载 App 才算正经产品」的心智。
- **量化决策规则**：当 **PWA 安装率 ≥ 8%** 且 **安装用户 D30 留存 ≥ 非安装用户的 2 倍** 时，说明装机需求真实存在，此时用 Capacitor 壳化上架（约 0.5 人月），**而非重写原生**。若安装率长期 < 3%，说明用户不需要「装」，App 立项即为浪费。
- **决策截止**：Phase 1 出口复盘时首次评估
- **拍板人**：主理人 + 架构师

| 4 | **首批语种** | 只写「2–4 语」，未指定 | 明确 **EN / ES / JA / PT-BR**，并主动排除中文作为 SEO 主推 | 避免最易获得的华人用户拉偏出海方向 |
| 5 | **熔断条件（Kill Criteria）** | 无 | **每阶段均设熔断条件** | 路线图必须能证伪。没有熔断条件的路线图，本质是许愿清单 |
| 6 | **NSM 严格定义** | 「高质量对弈局数（完成且双方非弃局）」 | 补充 5 条判定规则 + WQG 分解公式 | 口径不严的北极星指标必然被刷；分解公式让指标可归因 |
| 7 | **埋点方案** | 无 | 新增 14 类必埋事件 + 命名与隐私规范 | 不埋点则整个 MVP 无法证伪 |
| 8 | **图标方案** | 未提及 | 明确统一 SVG 图标库，**禁止 emoji 作为功能图标** | 跨平台渲染不一致、无法着色、无障碍语义缺失 |
| 9 | **规模类阈值全面校准**（v1.1 新增） | PRD 未给量化门槛 | Phase 0 废除流量型出口指标；Phase 1 MAU 12,000；Phase 2 MAU 150,000 | D6 确认无 KOL 资源，纯 SEO 冷启动需 3–6 个月才起量，原阈值会触发错误熔断 |
