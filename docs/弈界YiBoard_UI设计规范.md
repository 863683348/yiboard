### 0.1 设计寄存器（双寄存器，边界必须清晰）

本产品同时存在两种设计寄存器，**不可混用**：

| 寄存器 | 覆盖页面 | 标杆 | 判断标准 |
|---|---|---|---|
| **Brand 品牌型**（设计即产品） | 首页、文化叙事页、学习落地页、商城落地页 | Xiangqi.com 的文化叙事、Arc Browser | 「独特性」——能不能被记住 |
| **Product 产品型**（设计服务产品） | 对弈页、大厅、排行榜、账户、设置 | Linear、Lichess、Raycast | 「赢得熟悉感」——老手是否立刻上手 |

分界线：**用户按下"落子开始"的那一刻，从 Brand 切到 Product。** Brand 区允许更大的字号跨度、真实摄影、非对称留白；Product 区一律克制、密排、功能优先。

### 0.2 三轴刻度（本项目标定值）

| 参数 | 取值 | 含义 |
|---|---|---|
| `DESIGN_VARIANCE` | **6** | 非对称布局。首页禁止居中式 Hero，强制分屏（内容左 / 实盘右） |
| `MOTION_INTENSITY` | **6** | 游戏产品，允许"落子"这类签名微交互与轻量持续动效（计时器脉冲），但禁止装饰性入场动画 |
| `VISUAL_DENSITY` | **按面分档** | 首页 4 / 对弈页 5 / 账户 5 / 大厅 6 / 排行榜 7 |

排行榜 7 = 驾驶舱模式：**不用卡片盒子，只用 1px 分隔线 + 等宽数字**。

### 0.3 平台轴

`web`（主）+ `PWA`（可安装、离线人机对弈）。iOS/Android App 后置，届时复用同一套 Token，仅替换布局层。

## 1. 设计语言与对标品牌

### 1.1 品牌声音三词（物理对象法，非形容词堆砌）

> **木刻的（Carved） · 沉着的（Patient） · 果断的（Decisive）**

参照物不是"科技感/高级感"，而是三个具体物件：**一块用了三十年的实木棋盘**、**一枚朱砂印章**、**一张 1970 年代的比赛记分表**。

### 1.2 设计语言命名：**格律 Lattice**

产品最核心、最不可替代的视觉资产不是 logo，而是**棋盘本身**——线的交叉与其上的黑白圆子。整套设计语言由此推导，只有三条母题：

| 母题 | 来源 | 落到 UI 的规则 |
|---|---|---|
| **格 Lattice（线）** | 棋盘的经纬线 | 一切分隔都是 **1px 线**，不是"卡片盒子"。表格行、列表、区块边界、设置分组，全部用 `divide-y` / `border-t` 的格律线组织。这同时天然满足高密度界面的要求 |
| **子 Stone（圆）** | 黑白棋子 | 一切"实体标识"都是**正圆**：头像、状态点、段位章、难度选择器、在线指示。圆是本产品唯一允许的"完全圆角"形状 |
| **朱 Seal（点）** | 印章 / 象棋"红先" | 品牌强调色 = 朱砂。用量极省，**每屏可见处 ≤ 2**。它标记的永远是"发起"与"此刻"：主 CTA、最后一手、轮到你走、成五连线 |

### 1.3 对标与反对标

| 对象 | 学什么 | 明确不学什么 |
|---|---|---|
| **Xiangqi.com** | 文化叙事的说服力（"以棋为媒"）、图形化棋子降低非华人门槛、无广告的克制感 | 信息层级偏平、首页偏 SEO 长文堆砌、视觉时代感偏旧 |
| **Gomoku.com** | 零门槛即玩、PWA、多语言铺量 | 纯工具感、无品牌记忆点、社区与文化为零 |
| **Lichess / Chess.com** | 对弈页的功能密度与键盘效率、棋谱区信息组织 | Chess.com 的广告位与拥挤度 |
| **Linear** | Product 区的克制、格律密排、暗色明度递进 | 它的靛蓝调性（本产品不用蓝作主色） |
| **雀魂** | 无（题材参考） | **明确不做二次元、不做立绘、不做抽卡式视觉** |

### 1.4 三条来自竞品的差异化设计决策

1. **首页 Hero 就是一盘真的能下的棋**（见 §7.1）。竞品全部用"标题 + 截图/插画"，我们直接把产品放进 Hero。这既是最强的转化装置，也从结构上根除了"千篇一律 Hero"。
2. **不做东方主义视觉**。不用龙纹、不用书法字体做界面、不用祥云边框、不用大红大金。字体走**中性现代的工业无衬线**，"中国性"由**颜色（朱/青/墨）+ 格律母题 + 真实器物摄影**承担。这是 Xiangqi.com 之外全球用户真正能接受的表达方式。
3. **不用米色/宣纸背景**。"中国棋类 → 宣纸米色底"是最容易掉进去的套路，且暖中性底色（奶油/沙色/纸色）已是 AI 生成设计的通病。页面底色走**冷中性"石"色**；木头的温度只出现在**棋盘主题**这一个地方，且用户可关。

## 2. 配色系统

### 2.1 配色叙事：五色（朱 · 青 · 松 · 姜 · 绛）

语义色不从 Tailwind 默认盘里取，而是从一套自洽的传统色里取，保证整体是**一家人**：

| 角色 | 名 | 浅色 | 暗色 | 白底对比度 | 用途 |
|---|---|---|---|---|---|
| `--accent` | **朱砂 Cinnabar** | `#BE4A2F` | `#E0664A` | 4.97:1 | 品牌强调 / 主 CTA / 最后一手 / 轮到你 |
| `--info` | **石青 Azurite** | `#1B5E7E` | `#58A6C8` | 7.13:1 | 链接 / 提示 / 合法落点 / 图表主序列 |
| `--success` | **松绿** | `#2E7D5B` | `#4CAF82` | 5.06:1 | 胜局 / 保存成功 / 连接正常 |
| `--warn` | **姜黄** | `#9A6B0A` | `#D9A441` | 4.76:1 | 读秒 <30s / 网络抖动 / 弱提醒 |
| `--danger` | **绛红** | `#C0293C` | `#F2555F` | 5.81:1 | 认输 / 超时判负 / 删除 / 表单错误 |

**为什么主色是朱砂，而不是又一个靛蓝**：
象棋规则里**红先**——发起对局的一方是红方。所以"开始对弈"这个产品里最重要的动作用朱砂，是有出处的，不是随便挑的品牌色。同时它绕开了 `#6366F1` 这个"一眼 AI"的 Tailwind 默认靛蓝。

### 2.2 朱砂（accent）与绛红（danger）的区分规则 —— 必须遵守

两者同为红族，仅靠色相区分不够（朱砂 hue≈12° 暖，绛红 hue≈353° 冷）。因此追加**形态区分规则**，这是硬约束：

| | 朱砂 `--accent` | 绛红 `--danger` |
|---|---|---|
| 允许的形态 | **实心填充**（按钮/徽章底/进度条）、品牌标记、1px 强调边 | **文字 + 1px 边框 + 8% 淡底 + 图标**；仅"破坏性确认按钮"可实心填充 |
| 是否必带图标 | 否 | **是**，必须 图标 + 文字，不得只用颜色 |
| 共现规则 | — | **同一容器内出现实心 danger 按钮时，该容器不得出现 primary 按钮** |

自查方法：把界面转成灰度，若"朱砂按钮"和"错误提示"仍能靠形态区分，则通过。

### 2.3 中性色（墨阶）—— 冷中性，非米色

浅色主题四级墨阶**全部 ≥4.5:1**（对 `--surface`），可放心用于正文：

```
--fg    #16191C  17.0:1   主文本
--fg-2  #3A4149  10.3:1   次级正文 / 表格主列
--muted #5A626A   6.2:1   说明 / 图标 / 未激活
--meta  #6F777F   4.6:1   元信息（阶梯下限，禁止再淡）
```

暗色主题用**明度递进表达层级，不用阴影**：
`--bg #0F1214` → `--surface #171B1E` → `--surface-hover #1F2428` → `--border #2A3034`

### 2.4 用量配比（四层结构）

- 中性色 **70–90%**（`--bg` / `--surface` / `--fg` / `--muted` / `--border`）
- 强调色 **5–10%**（`--accent`，每屏可见 ≤2 处）
- 语义色 **0–5%**（success / warn / danger / info）
- 效果色 **<1%**（焦点环、遮罩）

### 2.5 双主题机制

**两条正交轴，不要耦合**：

```
轴 1 明暗：  :root  |  [data-theme="dark"]     （用户选择，回落 prefers-color-scheme）
轴 2 棋盘：  [data-board="ink" | "kaya" | "slate"]   （用户在设置里独立选择）
```

棋盘主题：

| 主题 | 说明 | 定位 |
|---|---|---|
| **墨石 Ink Stone** | 中性灰盘 + 灰线 | **默认**。与产品 UI 同源，现代、克制 |
| **榧木 Kaya** | 暖木盘 + 棕线 | 传统爱好者选项。**木色只出现在棋盘内，绝不外溢到页面背景** |
| **青石 Slate** | 冷灰高对比 | 无障碍首选，棋子与棋线对比最大 |

### 2.6 暗色下的 accent 反转说明

暗色主题里 `--accent` 提亮为 `#E0664A`，且**填充按钮改用深色字**（`--accent-on: #180B07`，对比 5.6:1）。暖橙底配深字比配白字对比更高也更耐看——这是刻意决策，不是疏漏。

## 3. 字体系统

### 3.1 字体选型（含拒绝理由）

| 角色 | 字体 | 覆盖 | 为什么是它 |
|---|---|---|---|
| `--font-display` | **Archivo**（可变：字重 100–900 + 字宽 62–125） | Latin / Cyrillic / Greek / Vietnamese | 工业级 Grotesque，终端平切、字面方正，就是"木刻感"。可变字宽让标题能做半窄设定，形成不可复制的版面辨识度。竞技属性强 |
| `--font-body` | **Inter**（可变） | Latin / Cyrillic / Greek / Vietnamese | 界面正文可读性基准，小字号表现最稳，多语言字符集最全 |
| CJK | **Noto Sans SC**（简）/ **Noto Sans TC**（繁） | zh-Hans / zh-Hant | 按 locale 动态追加，不全局加载 |
| 泰语 | **Noto Sans Thai** | th | 按 locale 追加（Gomoku.com 已铺泰语，我们必须跟） |
| `--font-mono` | **JetBrains Mono** | — | **仅限**棋谱记谱、计时器、ELO、比分、邀请码 |

**被主动拒绝的选项**：Playfair / Cormorant / Fraunces / Lora / Crimson（展示衬线 + 斜体 + 小型大写标签 = 2026 年 AI 生成设计的默认路线）；IBM Plex / Space Grotesk / DM Sans / Outfit / Plus Jakarta（训练数据默认值）；**任何书法体、隶书体、毛笔体做界面字**（东方主义陷阱，且多语言下必然崩）。

### 3.2 字号阶梯（8 级 + 1 个 display）

| Token | px | 用途 |
|---|---|---|
| `--text-xs` | 12 | 元信息 / 徽章 / 表尾 |
| `--text-sm` | 14 | 次级正文 / 表格 / 棋谱 |
| `--text-base` | 16 | **正文基准** |
| `--text-lg` | 18 | 强调正文 / 列表主行 |
| `--text-xl` | 20 | 卡片标题 / 计时器 |
| `--text-2xl` | 24 | 区块标题 |
| `--text-3xl` | 32 | 页面标题 |
| `--text-4xl` | 40 | 次级 Hero |
| `--text-display` | `clamp(40px, …, 68px)` | **仅首页 Hook 标题，一屏一次** |

正文不得小于 14px；`--text-xs` 仅用于非关键元信息。

### 3.3 字重（三级）

`400 Read` / `510 Emphasize` / `590 Announce`。
Noto Sans SC 无可变轴 → CJK 下自动回落 `500` / `700`（已在 CSS `:lang()` 中处理）。

### 3.4 字距规则（含中文覆盖 —— 这条最容易被做错）

| 场景 | 字距 |
|---|---|
| Display ≥40px（拉丁） | `-0.025em` |
| 32px / 24px（拉丁） | `-0.02em` / `-0.015em` |
| 正文 | `0` |
| 12–13px 小字 | `+0.01em` |
| **ALL CAPS** | **`+0.08em`（强制）** |
| **中日韩全部字号** | **`0`（负字距会把汉字挤在一起）** |

同时 CJK 正文行高提到 **1.75**（拉丁为 1.6）。ALL CAPS 规则不适用于中文。

### 3.5 多语言排版约束（15+ 语言是 MVP 需求，必须提前设计）

- 按钮**禁止固定宽度**。德语 `Freundschaftsspiel starten` 约为英文 2.4 倍长；CTA 用 `min-width` + 自适应，**且禁止对 CTA 做文本截断**。
- 标题禁止 `white-space: nowrap`；`--text-display` 已用 `clamp()` 防止长词溢出移动端。
- 数字一律 `tabular-nums`（表格、计时器、ELO、比分）——已在 CSS 全局基线中设置。
- 使用**逻辑属性**（`margin-inline-start` / `padding-inline`）而非 `left/right`，为后续阿拉伯语 RTL 留出通路。
- 字体按 locale 子集加载，`font-display: swap`，避免为英语用户下载 CJK 字体（数 MB 级差异）。

## 4. 间距 / 圆角 / 阴影 / 动效尺度

### 4.1 间距（4px 基准网格，8px 节奏）

仅允许：`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80`
禁止出现 `5 / 7 / 13 / 15 / 18 / 22 / 30` 等非标值。

节区节奏：桌面 80 / 平板 48 / 手机 32。
容器沟槽：桌面 24 / 平板 16 / 手机 12。容器最大宽 1200px；阅读型内容 680px。

### 4.2 圆角（4 级，上限 14px）

| Token | px | 用途 |
|---|---|---|
| `--radius-sm` | 6 | 按钮 / 输入框 / 徽章 |
| `--radius-md` | 10 | 卡片 / 面板 / 下拉 |
| `--radius-lg` | 14 | 棋盘容器 / 模态（**卡片类上限**） |
| `--radius-pill` | 9999 | 棋子 / 头像 / 段位章 / 胶囊标签 |

**禁止 ≥24px 的卡片圆角**（过度圆滑 = AI 味）。

### 4.3 阴影 / 层级（三级，环优先）

| Token | 浅色 | 暗色 |
|---|---|---|
| `--elev-flat` | `none` | `none` |
| `--elev-ring` | `0 0 0 1px var(--border)` | 同左 |
| `--elev-raised` | `0 1px 2px /5% + 0 4px 10px /6%` | **改用 1px 环**（暗色靠 surface 提亮表达抬升） |
| `--elev-overlay` | `0 8px 28px /14%` | `0 12px 36px /60%` |

**硬规则**：同一元素上**禁止同时出现** `1px border` 与 `blur ≥16px` 的阴影（幽灵卡片）。卡片默认 `border + 无阴影`。

### 4.4 动效

| Token | 时长 | 场景 |
|---|---|---|
| `--motion-instant` | 90ms | 按下 / 开关 |
| `--motion-fast` | 150ms | hover / 选中 |
| `--motion-base` | 200ms | 展开 / Toast |
| `--motion-slow` | 300ms | 模态 / 页面过渡 |
| `--motion-stone` | 160ms | **落子（签名微交互）** |

**签名微交互「落子」**：棋子从 `scale(0.86)` → `scale(1)`，缓动 `cubic-bezier(0.16, 1, 0.3, 1)`（只减速、**不回弹**——真棋子落到盘上不会弹起来），同时 1px 投影由 0 渐入到位。落点周围**不做涟漪、不做发光**。
`prefers-reduced-motion` 下：棋子直接出现，仅保留一帧朱砂描边确认。全局动效已在 CSS 中降级为 1ms。

计时器 <10s 时叠加 1s 周期的脉冲（`MOTION_INTENSITY 6` 允许的唯一持续动效），同样受 reduced-motion 约束。

## 5. 核心组件 Token 草案

> 完整取值见 `design-tokens.css` §5 / `design-tokens.json` `component`。此处给出规则与状态要求。

### 5.1 按钮

| 变体 | 背景 | 前景 | 边框 | 用量规则 |
|---|---|---|---|---|
| **Primary** | `--accent` | `--accent-on` | 无 | **每屏 ≤1 个** |
| **Secondary** | `--surface` | `--fg` | `--border-strong`（hover → `--accent`） | 承载 90% 次级操作 |
| **Ghost** | 透明 | `--muted`（hover → `--fg`） | 无 | 工具栏 / 图标按钮 |
| **Destructive** | `--danger` | `#FFFFFF` | 无 | 认输 / 删号 / 清数据；**该容器内不得同时出现 Primary** |

尺寸：`sm 32px` / `md 40px` / `lg 48px`；圆角 `--radius-sm`；字重 510；图标间距 8px。
**触摸约束**：`sm` 在触摸端必须外扩不可见热区至 44×44px。

### 5.2 输入框

`label 永远可见`（禁止只用 placeholder 当 label）；错误信息紧贴字段下方，不只在表单顶部汇总；helper text 常驻不跳动（避免 CLS）。
焦点态：`--input-border-focus: --accent` + `--input-ring-focus: --accent-ring`。

### 5.3 卡片

`--surface` 底 + `1px --border` + `--radius-md` + **无阴影**；hover 时边框转 `--accent`。
**禁止彩色左边框强调**（`border-left: 3px solid accent` 是 AI 设计特征）。

### 5.4 棋盘容器与点阵（本产品的核心组件）

```
--boardframe-bg      : var(--board-surface)   /* 随 data-board 切换 */
--boardframe-border  : var(--board-frame)
--boardframe-radius  : var(--radius-lg)       /* 14px */
--boardframe-pad     : 16px                   /* 外边到最外侧线 */
--board-line-w       : 1px
--board-line-w-edge  : 1.5px                  /* 外框略粗，形成"盘沿" */
--board-star-size    : 6px                    /* 星位 / 天元 */
--stone-scale        : 0.86                   /* 棋子直径 / 格宽 */
```

**几何硬规则**：
1. 棋盘永远是**正方形**，且**永不进入滚动容器**。
   `--board-max: min(640px, calc(100vh - 260px))`；手机 `min(100vw - 24px, calc(100vh - 220px))`。
2. 格宽 = 棋盘边长 / (N-1)，由容器反推，不写死。
3. **交叉点最小触摸尺寸 28px**（`--cell-min-touch`）。15×15 棋盘在小屏上必然低于此值 —— 此时**强制启用两段式落子**：手指按下显示放大预览游标 → 抬起前可拖动微调 → 松手确认。这是围棋类 App 的成熟解法，比强行放大 44px 热区（会互相重叠）正确。

**落点标记一律"形状 + 颜色"双编码**（禁止只靠颜色）：

| 标记 | 形状 | 颜色 |
|---|---|---|
| 最后一手 | 环形描边 | `--accent` |
| 合法落点 | 实心小圆点 | `--info` 34% |
| AI 建议 | 虚线环 | `--info` 62% |
| 成五连线 | 贯穿实线 + 圆头端点 | `--accent` |
| Renju 禁手 | 叉形 | `--danger` |

**象棋红黑的色盲安全处理**（关键）：红绿色盲下"红子"与"黑子"色相接近。因此**不靠字色区分，靠棋子盘面明度区分**：
红方 = 浅色盘面 `#F4ECE4` + 深红字 `#A32B24`；黑方 = 深色盘面 `#22262A` + 浅字 `#F2F4F5`。灰度下依然一眼可辨。

### 5.5 徽章 / 段位章

胶囊形（`--radius-pill`），高 22px，12px 字，字重 510，字距 +0.01em。色调 6 种：neutral / accent / success / warn / danger / info。

**段位体系 —— 已决（2026-08-07，总监裁定）：九品 + 段位双轨 + ELO 分档映射 + 英文译名。**

> **[设计侧修正] 品级方向已翻转，与我 v0.1 草案相反 —— 请以本表为准。**
> v0.1 草案写的是「一品 → 九品」升序（源自中国古代官阶"一品最高"）。但全球棋类平台（围棋/将棋/跆拳道）通用的是 **kyu 降序**：**九品是入门，一品是品级最高，再往上才进段位**。总监裁定的译名序列「九品=Ninth Grade … 初段=First Dan」正是这个方向。海外用户（本产品主要受众）的既有认知只有这一种，采用它。
> **影响**：石色渐变的方向随之翻转（原草案把石青给了九品，现改给一品）。`design-tokens` 中 rank 键名已由 `tier1to3/4to6/7to9` 改为语义命名 `gradeEntry/gradeMid/gradeHigh/dan`，避免数字歧义。

**完整阶梯（低 → 高，18 级 = 9 品 + 9 段）**

| 中文 | 英文 | 榜单缩写 | ELO 区间 | 色阶 Token |
|---|---|---|---|---|
| 九品 | Ninth Grade | `G9` | < 1000 | `--rank-grade-entry` 砺石 |
| 八品 | Eighth Grade | `G8` | 1000–1099 | `--rank-grade-entry` |
| 七品 | Seventh Grade | `G7` | 1100–1199 | `--rank-grade-entry` |
| 六品 | Sixth Grade | `G6` | 1200–1299 ← **新账号起始档** | `--rank-grade-mid` 苔青 |
| 五品 | Fifth Grade | `G5` | 1300–1399 | `--rank-grade-mid` |
| 四品 | Fourth Grade | `G4` | 1400–1499 | `--rank-grade-mid` |
| 三品 | Third Grade | `G3` | 1500–1599 | `--rank-grade-high` 石青 |
| 二品 | Second Grade | `G2` | 1600–1699 | `--rank-grade-high` |
| 一品 | First Grade | `G1` | 1700–1799 | `--rank-grade-high` |
| 初段 | First Dan | `D1` | 1800–1899 | `--rank-dan` 朱砂 |
| 二段 | Second Dan | `D2` | 1900–1999 | `--rank-dan` |
| 三段 | Third Dan | `D3` | 2000–2099 | `--rank-dan` |
| 四段 | Fourth Dan | `D4` | 2100–2199 | `--rank-dan` |
| 五段 → 八段 | Fifth → Eighth Dan | `D5`–`D8` | 每档 100 分递进 | `--rank-dan` |
| 九段 | Ninth Dan | `D9` | ≥ 2600 | `--rank-dan` |

> ELO 分档为 100 分等距（起始 1200 落在六品），便于新用户在前 10 盘内看到第一次升档。**具体阈值最终以架构师的 ELO 实现为准**，若 K 因子导致分布偏移，只需整体平移区间、不影响任何设计 Token。

**展示规则（三种场合，不可混用）**
1. **排行榜行**（列宽紧张）：中文 / 日文 locale 用 2 字全称（「三品」天然紧凑）；拉丁语系及其余 locale 用缩写 `G9`…`D9`。两者均等宽右对齐，并配 `aria-label` 播报全称。
2. **个人资料 / 段位页**：用全称「三品 Third Grade」双语并置。
3. **对局页玩家条**：中文界面用「三品」，其他语种用缩写 + 段位章，避免多语言下撑破 56px 玩家条。

**段位章形态**：正圆石章（棋子母题复用），直径 20px，内嵌品级数字，描边取对应色阶。
**禁止金/银/铜三色套路，禁止奖杯与奖牌 emoji，禁止环形进度圈 + 渐变的通用仪表盘套路。**

> **[advisory · 不阻塞]** `Ninth Grade` 在英语里与"九年级"同形（美制 9th grade = 14 岁学段）。建议段位页首次展示时给一条阶梯图例（`Grade 9 (beginner) → Grade 1 → Dan 1 → Dan 9`），一次性消解歧义；缩写 `G9/D1` 本身无此问题。若后续本地化反馈仍有困惑，备选译名是 `Rank 9 / Dan 1`（改动只在文案层，不动 Token）。

### 5.6 排行榜行（VISUAL_DENSITY 7 · 格律密排）

--lbrow-border-self  : var(--accent)

前三名靠**字重 + 墨色**区分（`--lbrow-rank-top-fg: --fg`），不用金银铜色块。

### 5.7 头像 / Tab / 计时器

- **头像**：永远正圆（棋子母题）。24 / 32 / 48px。`--avatar-ring-active: --accent` 表示"轮到该玩家走棋"。
- **Tab**：高 44px，激活态 `--fg` + 2px 朱砂下划线；激活态图标切 Phosphor `fill` 权重。
- **计时器**：等宽字体，`--text-xl`。常态 `--fg` / 非己方回合 `--meta` / <30s `--warn` / <10s `--danger` + 脉冲。

### 5.8 组件状态矩阵（每个交互组件必须覆盖）

| 状态 | 要求 |
|---|---|
| Default / Hover / Focus-visible / Active / Disabled | 全组件必备 |

| **Edge** | 超长用户名（多语言）、ELO 四位数、300 手长棋谱、并列名次 |

## 6. 图标系统（锁定，不可协商）

### 6.1 锁定：**Phosphor Icons**

| 项 | 值 |
|---|---|
| 库 | **Phosphor Icons** |
| 包 | `@phosphor-icons/react`（Web 组件版 `@phosphor-icons/web`） |
| 许可 | MIT |
| 锁定权重 | `regular`（默认） / `fill`（仅激活态） / `bold`（仅 16px 光学补偿） |
| 尺寸 | **16 / 20 / 24 px**，三档，无例外 |
| 颜色 | `--icon-fg: --muted`；激活 `--icon-fg-active: --accent` |

**为什么是 Phosphor 而不是 Lucide/Tabler/Heroicons**：
1. Phosphor 在**同一家族内**提供 `regular` 与 `fill` 两种权重 —— 底部 TabBar 的"未选中描边 / 选中填充"是移动端标配，Lucide 几乎没有填充变体，用它就得混第二套库。
2. 9000+ 图标覆盖本产品长尾需求（trophy / medal / globe / translate / timer / clock-countdown / arrow-u-up-left / flag / handshake / crown / chats）。
3. 相对不那么"AI 默认"（Lucide 已是生成式产出的通用选择）。

**尺寸档位规则**：16px（行内 / 徽章内，**用 `bold` 权重做光学补偿**，否则描边太细）；20px（按钮内，`regular`）；24px（独立图标 / 导航，`regular`，激活态 `fill`）。

### 6.2 棋种自绘图标（Phosphor 没有）

五子棋 / 象棋 / 围棋 / 六子棋 / 黑白棋需要自绘。**必须在 Phosphor 的 24×24 网格上绘制**，匹配其描边宽度（24px 下约 1.5px）、圆头端点、圆角接合，做到与 Phosphor 混排时无法分辨来源。

建议语义：五子棋 = 3×3 格 + 一条斜向五连；象棋 = 圆子 + 楚河界线；围棋 = 星位点阵；六子棋 = 六连点；黑白棋 = 半黑半白圆。**全部单色描边，不做多色不做立体。**

### 6.3 禁止 emoji 作功能图标（P0）

**任何 emoji 不得作为功能图标出现在 UI 中。**

```regex
[\u{1F300}-\u{1F9FF}\u{2600}-\u{26FF}\u{2700}-\u{27BF}]
```

具体替换对照（本产品高危位）：

| 禁止 | 替换 |
|---|---|
| 奖杯 emoji（排行榜） | `Trophy`（Phosphor） |
| 奖牌 emoji（段位） | 段位石章（自绘正圆 + 品级数字） |
| 地球 emoji（语言切换） | `Translate` 或 `Globe` |
| 火焰 emoji（连胜） | `Flame`（Phosphor，单色描边） |
| 国旗 emoji（国家榜） | **SVG 国旗资源**（`flag-icons`），非 emoji —— emoji 国旗在 Windows 上根本不渲染，这是功能 bug 不只是规范问题 |
| 时钟 emoji（计时） | `Timer` / `ClockCountdown` |
| 星星 emoji（收藏） | `Star`（`regular` / `fill` 切换） |

**唯一例外**：用户生成内容（聊天消息、个人签名）中的 emoji 允许原样显示。

- **断线**：顶部常驻细条提示 + 自动重连倒计时，**不弹整页遮罩**（对局中弹遮罩 = 判负风险）。

### 7.5 SEO 落地页排版（Brand 寄存器 · DENSITY 3 · 新增，对齐 PM 增长策略）

PM 规划已确认：**无海外 KOL 资源，冷启动主渠道 = SEO 慢热**，且要求「每个棋种 + 每个语种有独立可索引 URL，Lighthouse SEO ≥ 95」。这意味着 SEO 长文内容**不是附属品，而是首屏之外的第二主战场**，必须有专门的排版规范——否则会变成竞品那种"首页堆一坨关键词长文"的观感灾难。

**URL 与页面矩阵**：`/{locale}/play/{game}` × 15 语种 × 5 棋种。每页共用同一套模板。

## 9. 给前端 Agent 的实现提示

1. **引入顺序**：`design-tokens.css` 必须在任何组件样式之前加载（已用 `@layer yb-tokens` 保证优先级可控）。
2. **取值来源唯一**：JS/TS 侧 `import tokens from './design-tokens.json'`；CSS 侧只用 `var(--*)`。**组件内出现裸 hex 视为构建失败**，建议加 stylelint 规则 `color-no-hex`（白名单 `#fff` `#000`）。
3. **两条主题轴分别落在 `<html>` 上**：`data-theme` 与 `data-board` 互不干扰，切换任一不得引起另一轴闪烁。首屏用内联脚本从 `localStorage` 预设，避免 FOUC。
4. **棋盘用 SVG 渲染**（非 Canvas）：交叉点可获焦、可 `aria-label`、可被屏幕阅读器遍历，且矢量缩放无锯齿。高频重绘的只有棋子层。
5. **字体分片加载**：Archivo + Inter 常驻；Noto Sans SC/TC/Thai 按 locale 动态注入；`font-display: swap`；用 `size-adjust` 减少 CJK 回落时的布局跳动。
6. **图标只装一个包**：`@phosphor-icons/react`。CI 加检查——若 `package.json` 出现 `lucide-react` / `@tabler/icons` / `@heroicons` / `react-icons`，构建失败。
7. **性能**：CLS < 0.1（helper text 与计时器区域预留固定高度）；棋盘图片/摄影用 AVIF+WebP + `srcset`；PWA 预缓存棋盘资源与 AI 引擎 wasm。
8. **Tailwind 使用者**：把 `design-tokens.json` 映射进 `theme.extend`（`colors` 指向 `var(--*)` 而非硬值，才能让两条主题轴生效）。
